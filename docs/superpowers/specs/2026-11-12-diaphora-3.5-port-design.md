# Design Document: Upgrading r2diaphora to Diaphora 3.5

- **Date:** 2026-11-12
- **Status:** Draft (Pending Builder Check & User Approval)
- **Target Upstream:** [joxeankoret/diaphora](https://github.com/joxeankoret/diaphora) v3.5 (`VERSION_VALUE = "3.4"` in schema/code, tag `3.5.0`)

---

## 1. Intent and Why

`r2diaphora` is currently a hard fork of Diaphora 2.0.6 that replaces SQLite with hardcoded `mysql.connector` (MariaDB) queries and rewrites `CIDABinDiff.read_function` in `r2diaphora/diaphora_r2.py` on top of a partial `idaapi_to_r2.py` wrapper. This causes three major problems:
1. **Outdated diffing engine:** It lacks 6+ years of Diaphora 3.x improvements (compilation unit discovery via LFA + `IDAMagicStrings`, ML-assisted matching, multimatch resolution, local affinity heuristics, call-diffing heuristics, and updated schema/indices).
2. **Severe performance bottleneck:** `diaphora_r2.py` issues multiple `r2pipe` IPC calls per basic block and per instruction (`aoj 1`, `axfj`, `axfq.`, `CC.`, `afbj.`) and re-fetches all flags (`fj`) per function to find switches, resulting in thousands of subprocess/socket round-trips per binary.
3. **Poor upgradeability & cross-platform bugs:** Upstream files were edited in place for MariaDB and r2, making upgrades a manual rewrite, and `signal.SIGALRM` is used for timeouts (which crashes on Windows with `AttributeError`).

The goal of this project is to upgrade `r2diaphora` to **Diaphora 3.5**, switch to **SQLite as the default database** while **maintaining MariaDB support**, **maximize export/diff performance**, and isolate all radare2 and MariaDB specifics into a **translation layer** so future Diaphora versions can be dropped in with minimal effort.

---

## 2. Goals, Non-Goals, and Anti-Goals

### Goals
- **Upgrade to Diaphora 3.5:** Include Diaphora 3.5's schema (`db_support/schema.py`), heuristics (`diaphora_heuristics.py`), diffing engine (`diaphora.py`), exporter (`diaphora_ida.py`), compilation unit analysis (`codecut/lfa.py`, `jkutils/IDAMagicStrings.py`), KOKA graph hashing (`jkutils/graph_hashes.py`), and ML scoring (`ml/`).
- **SQLite Default + MariaDB Support:**
  - Default to SQLite `.sqlite` file databases (identical to upstream Diaphora 3.5 so databases generated by IDA Diaphora 3.5 and `r2diaphora` are directly cross-compatible).
  - Retain MariaDB support via `--db-backend mariadb` (CLI) / `backend="mariadb"` (Python API) and `r2diaphora-db` (`clean`, `config`).
- **High-Performance Bulk R2 Pre-fetching:**
  - Eliminate per-instruction and per-basic-block `r2pipe` calls by pre-fetching binary-wide tables once (`ij`, `iSj`, `aflj`, `fj`, `izj`, `axj`, `CCj`, `tn`) and per-function instruction/CFG data in bulk (`agfj @ <ea>` + a single contiguous `aoj` per function or block range).
  - Parse PE64 `.pdata` (`RUNTIME_FUNCTION` entries) and exception handler flags (`try.*`) before `aaaa` (plus optional PDB loading via `--pdb`) so radare2 discovers accurate function boundaries matching IDA.
- **Upgradeable Translation Layer (`r2diaphora/ida_shim/`):**
  - Provide mock `idc`, `idaapi`, `idautils`, and `ida_*` Python modules in `sys.modules` so upstream `diaphora_ida.py`, `codecut/lfa.py`, `codecut/basicutils_7x.py`, `jkutils/graph_hashes.py`, and `jkutils/IDAMagicStrings.py` run unmodified in headless/batch mode (`idaapi.cvar.batch = True`).
- **Cross-Platform Compatibility:**
  - Replace Unix-only `signal.SIGALRM` with cross-platform timeout handling (`threading` / `concurrent.futures`) and fix Windows plugin/binary path resolution for `radare2` and `r2ghidra`.
- **Empirical Accuracy Verification on `calc.exe`:**
  - Compare the SQLite database generated for `C:\Windows\System32\calc.exe` by Diaphora 3.5 in IDA against `r2diaphora` + `r2ghidra`, verifying schema parity, function discovery, CFG/topological metrics (`nodes`, `edges`, `cyclomatic_complexity`, `md_index`, `kgh_hash`, `tarjan_topological_sort`), `bytes_hash`, `function_hash`, `mnemonics_spp`, constants, callers/callees, and self-diff / cross-diff matching ratios.

### Non-Goals
- **Interactive IDA Qt GUI emulation:** `diaphora_ida_ui.py` and Qt widget classes (`PluginForm`, `GraphViewer`) are only stubbed for headless import; `r2diaphora` outputs SQLite/MariaDB databases, `.diaphora` result files, and standalone HTML diff reports (`HtmlResults`).
- **Hex-Rays Microcode (`mba_t`) emulation:** `r2ghidra` does not produce Hex-Rays `m_*` microcode instructions. `ida_hexrays.gen_microcode()` will return `None`, causing `CIDABinDiff.get_microcode()` to return `[], []` (which Diaphora 3.5 natively supports when microcode is disabled/unavailable). Decompilation and AST hashing (`pdgj` → `CAstVisitor`) *are* supported.

### Anti-Goals
- **Do not fork upstream SQL queries or exporter logic in place:** Never rewrite `diaphora_heuristics.py` or `diaphora.py` to hardcode `%s` placeholders or `$MAIN$`/`$DIFF$` strings.
- **Do not issue `r2pipe` commands inside instruction loops:** Every instruction-level query in the shim (`decode_insn`, `print_insn_mnem`, `GetDisasm`, `get_item_size`, `get_bytes`, `get_operand_value`, `CodeRefsFrom`, `DataRefsFrom`, `GetCommentEx`, `get_switch_info`) must be served from the pre-fetched in-memory cache (`O(1)` dict lookup).

---

## 3. Constraints

1. **Database Cross-Compatibility:** An `.sqlite` database exported by `r2diaphora` must be loadable and diffable by upstream IDA Diaphora 3.5 (and vice versa). Therefore, the SQLite schema, table names, column types, and `VERSION_VALUE` (`"3.4"` in Diaphora 3.5.0) must match upstream `db_support/schema.py` 100%.
2. **Windows + Linux + macOS Support:** Must run cleanly on Windows (where `signal.SIGALRM` does not exist, SQLite file locks are strict, and `r2.bat`/`radare2.exe` may live in `%USERPROFILE%\tools\radare2\bin` or `PATH`) as well as POSIX platforms.
3. **Backward Compatibility for Existing `r2diaphora` Users:**
   - Preserve CLI flags (`file1`, `file2`, `-f`, `-nbbs`, `-o`, `-d {pdc,ghidra}`, `-nd`, `-a`, `-t`) and add `--db-backend {sqlite,mariadb}`, `--db1`, `--db2`, and `--pdb`.
   - Preserve public Python API in `r2diaphora/__init__.py` (`generate_db_for_file`, `dbname_for_file`, `compare_dbs`, `get_function_details`, `get_db_attrs`, `get_db_attrs_path`, `drop_all`, `drop_db`, `sample_db_exists`, `HtmlResults`) and scripts (`r2diaphora-db`, `r2diaphora-bulk`).

## 4. Approaches Considered

### Approach 1: Upstream-Intact Core + Bulk-Cached `ida*` Translation Layer + Dual-Backend DB Adapter (Selected)
- **Description:** Keep upstream Diaphora 3.5 files intact under `r2diaphora/upstream/`. Inject a bulk-cached `ida*` shim package into `sys.modules` before importing `diaphora` / `diaphora_ida`, and hook `diaphora.sqlite3_connect` with a dual-backend DB adapter (native `sqlite3` by default; SQL-translating `mysql.connector` cursor when MariaDB mode is active).
- **Pros:** Native SQLite speed; 10–50x faster r2 export via bulk JSON pre-fetching; near-zero diff against upstream Diaphora 3.5 so future 3.x releases drop right in; automatically supports LFA compilation units, `IDAMagicStrings`, and KOKA graph hashes.
- **Cons:** Requires implementing a complete headless surface for the `ida*` functions called by `diaphora_ida.py`, `codecut`, `graph_hashes.py`, and `IDAMagicStrings.py` (~45 functions/classes).

### Approach 2: Subclass `CBinDiff` with Custom `CR2BinDiff` Exporter
- **Description:** Use upstream `diaphora.py` for diffing, but skip `diaphora_ida.py` and maintain a custom `CR2BinDiff` exporter in `diaphora_r2.py`.
- **Pros:** Slightly fewer `ida_*` mock classes needed.
- **Cons:** Duplicates all feature extraction logic (`read_function`, `process_basic_block`, `extract_all_features`, `save_compilation_units`, `CKoretKaramitasHash`); breaks whenever upstream adds or reorders fields in `FUNCTION_FIELDS`.

### Approach 3: In-Place Fork of Upstream Diaphora 3.5
- **Description:** Edit `diaphora.py`, `diaphora_ida.py`, and `diaphora_heuristics.py` directly to call `r2pipe` and support MariaDB/SQLite branches.
- **Pros:** None over Approach 1.
- **Cons:** Destroys upgradeability and repeats the exact maintenance trap of the v2.0 port.

**Decision:** Selected **Approach 1** per user priority (performance first, maintainability second).

### 5.2 High-Performance Bulk R2 Pre-fetching (`r2diaphora/ida_shim/cache.py`)

When opening a binary in `R2BinaryCache(input_path, decompiler="ghidra", load_pdb=False, analyze_all=False)`, we execute a structured initialization pipeline instead of ad-hoc per-instruction queries:

1. **Binary Open & Pre-Analysis Setup (`r2pipe`):**
   - Resolve `radare2` executable from `PATH`, `$R2_HOME/bin`, `$R2_PREFIX/bin`, or `%USERPROFILE%\tools\radare2\bin` (ensuring Windows works even when `r2` is not in the default shell `PATH`).
   - Open via `r2pipe.open(input_path, flags=["-2"])` and configure:
     - `e scr.color=0; e asm.flags=false; e asm.bytes=false; e io.cache=true; e bin.relocs.apply=true`
   - **Optional PDB loading (`--pdb` or auto if local `.pdb` exists):** Run `idp` and `af @@ pdb.*` before `aaaa` when requested.
   - **PE64 `.pdata` & Exception Handler Function Seeding (Critical for Accuracy):**
     - On PE64 binaries (`ij.bin.bintype == "pe"` and `ij.bin.bits == 64`), read `section..pdata` in one bulk command (`pxj <size> @ section..pdata`), unpack the 12-byte `(BeginAddress, EndAddress, UnwindInfoAddress)` `RUNTIME_FUNCTION` entries, and issue a single batched command defining function starts (`af @ <imagebase + BeginAddress>`) plus any `try.*.filter` / `try.*.catch` flags *before* running `aaaa`.
     - As verified on `calc.exe`, this prevents `r2` from merging tail-called functions (like `wWinMainCRTStartup` → `__wmainCRTStartup` or `__security_check_cookie` → `_guard_dispatch_icall`) and recovers missing functions (`_tlgEnableCallback`, `__report_gsfailure`, `pre_c_init`, `pre_cpp_init`, etc.).
   - **FLIRT Signatures & Analysis:** Run `scan_libs()` (`zfs <sigs>/*.sig`) and `aaaa`.

2. **One-Shot Binary-Wide Bulk Queries (Executed Once per Binary):**
   - `ij` → `bin_info` (architecture, bitness, imagebase `baddr`, compiler/language).
   - `iSj` → `segments` list (sorted by `vaddr`, used for `O(1)`/`O(log N)` `get_segm_start(ea)` and `get_segm_by_name(name)`).
   - `aflj` → `functions` dict keyed by `offset` (sorted function list for `Functions()`, `get_func(ea)`, `get_next_func(ea)`, `get_prev_func(ea)`, and interval tree / bisect lookup `func_containing(ea)`).
   - `isj` + `fj` → `names` dict (`{ea: (name, realname/demangled)}`) and `switches` map (pre-indexed by function address so `get_switch_info(ea)` is an `O(1)` lookup instead of calling `fj` on every function!).
   - `izj` → `strings_by_ea` dict (`{vaddr: {"string": s, "length": l, "type": t}}`) so `get_strlit_contents(ea)` and `idautils.Strings()` require zero extra `r2pipe` calls.
   - `axj` → Global cross-references table indexed into `code_refs_from[ea]`, `code_refs_to[ea]`, `data_refs_from[ea]`, and `data_refs_to[ea]`. *(Fallback: if `axj` is empty on older r2 versions, populate from `agfj` `xrefs`/`refs` plus `axffj` per function.)*
   - `CCj` → `comments_by_ea` (`{ea: comment}`) so `GetCommentEx` / `get_cmt` / `get_func_cmt` are `O(1)` dict lookups instead of calling `CC. @ ea` on every instruction.
   - `tn` → `no_ret_funcs` set.
   - Full executable section bytes (`p8j` per executable segment) cached into a `memory_slices` bytearray map so `get_bytes(ea, size)` slices directly from Python `bytes` in `O(1)` without calling `p8j` per instruction!

3. **Per-Function Bulk Fetch (Executed Once per Exported Function):**
   - Instead of calling `aoj 1 @ head` for every instruction in `Heads(block.start_ea, block.end_ea)`:
     - Issue **one** `agfj @ <func_ea>` call to get the basic blocks (`blocks`: `addr`, `size`, `jump`, `fail`, and `ops`) and **one** `aoj <ninstrs> @ <block_ea>` per basic block (or one `aoj` across the contiguous function range) to get `opex` (operand types `imm`, `mem`, `reg`, displacements, values) and `mask`.
     - Populate `insn_cache[ea]` with pre-built `insn_t` objects (including `decoded_size` computed from `mask` or operand `offb`, `ops`, `mnem`, `disasm`, `size`, `bytes`).
   - Result: When `CIDABinDiff.read_function(f)` and `CKoretKaramitasHash.calculate(f)` iterate over `FlowChart(func)` and `Heads(block.start_ea, block.end_ea)`, **100% of calls inside the loop hit `insn_cache` and `R2BinaryCache` in memory with 0 `r2pipe` calls!**

#### Normalization Details for IDA Parity
1. **Function Naming (`sub_` vs `fcn.`):**
   - Upstream Diaphora 3.5 heuristics (`diaphora_heuristics.py` and `diaphora.py`) heavily check `substr(f.name, 1, 4) = 'sub_'` and `name.startswith("sub_")`.
   - In `r2`, auto-named functions are named `fcn.140001390`.
   - Our shim normalizes `fcn.<hex>` → `sub_<hex>` (and strips `pdb.` / `sym.` prefixes from symbol-backed functions) so all 40+ SQL heuristics in `diaphora_heuristics.py` that filter on `sub_` work out-of-the-box without modifying a single SQL query!
2. **Processor Name (`program.processor`):**
   - IDA sets `get_idp_name()` to `"metapc"` on x86/x86_64, which becomes `"metapc64"` in `save_callgraph()`.
   - Our shim maps `r2`'s `arch == "x86"` to `"metapc"` so cross-diffing an IDA-generated SQLite DB against an `r2diaphora`-generated SQLite DB sets `self.is_same_processor = True` and enables all `HEUR_FLAG_SAME_CPU` heuristics!
3. **Instruction Masking (`bytes_hash`):**
   - In IDA, `get_decoded_instruction(ea)` subtracts operand offset `offb` for `o_mem`, `o_imm`, `o_far`, `o_near`, `o_displ` so relocatable immediates/displacements are excluded from `bytes_hash`.
   - In `r2`, `aoj` provides `mask` (e.g., `ff000000` for `cmp rax, -3` or `ffff` for `xor edx, edx`) and `opex.operands`. In `ida_shim`, `decode_insn` computes `offb` from the first non-register operand bitmask (`mask` trailing `00` bytes) so `get_decoded_instruction` + `get_bytes(current_head, decoded_size)` produces the exact prefix opcode bytes that IDA hashes!

### 5.4 Dual-Backend Database Adapter (`r2diaphora/db_backend.py`)

Upstream Diaphora 3.5 calls `diaphora.sqlite3_connect(db_name)` everywhere in `diaphora.py` and `diaphora_ida.py`.

We hook `diaphora.sqlite3_connect` with a configurable factory supporting two backends:

#### 1. SQLite Backend (Default: `backend="sqlite"`)
- Calls Python's native `sqlite3.connect(db_path, check_same_thread=False)` directly with `row_factory = sqlite3.Row`.
- Zero wrapper overhead.
- Database naming:
  - By default in CLI: `<binary_path>.sqlite` (or `~/.r2diaphora/dbs/<sha256>.sqlite` when `generate_db_for_file(filepath)` is called without an explicit output path, configurable via `db_dir`).
  - Supports passing existing `.sqlite` files directly to `r2diaphora db1.sqlite db2.sqlite` (matching `diaphora.py db1.sqlite db2.sqlite`).

#### 2. MariaDB Backend (`backend="mariadb"`, `--db-backend mariadb`)
- Connects to MariaDB using `mysql.connector.connect(...)` with credentials from `~/.r2diaphora/db.json` (configured via `r2diaphora-db config`).
- Returns a `MariaDBConnectionAdapter` and `MariaDBCursorAdapter` that transparently translate Diaphora 3.5's SQLite operations:
  - `PRAGMA ...` and `analyze` → no-op.
  - `BEGIN transaction` → `db.start_transaction()`.
  - `attach "<diff_db>" as diff` → stores `self.diff_db = <diff_db>` on the connection.
  - `detach "diff"` / `detach "<diff_db>"` → clears `self.diff_db`.
  - Schema translation on `create_schema()` / `create_indices()`:
    - Creates database `` `<db_name>` `` with `utf8mb4` and `USE `<db_name>``.
    - Translates SQLite `id integer primary key` → `id integer primary key auto_increment`.
    - Translates `address text unique` / `rva text unique` / `start_ea text unique` → `varchar(255) unique` (since MariaDB cannot create unique keys on unbounded `TEXT`).
    - Translates `TEXT` columns in `INDICES` (`schema.INDICES`) to include prefix lengths (e.g., `pseudocode(768)`, `assembly(768)`, `mnemonics(512)`, `names(512)`, `clean_assembly(768)`, `clean_pseudo(768)`, `kgh_hash(768)`, etc.) where required by InnoDB index size limits.
  - Query translation on `execute()` / `executemany()`:
    - Replaces `main.` → `` `<self.main_db>`. `` and `diff.` → `` `<self.diff_db>`. ``.
    - Replaces `?` parameter placeholders (outside string literals) → `%s`.
    - Translates `insert or ignore into` → `insert ignore into`.
    - Translates SQLite `cast(x as real)` → `cast(x as double)` and `order by f.source_file = df.source_file` (handling `NULL` safely).
    - Wraps returned dict rows in a `RowAdapter` supporting both `row["col"]` (by column name) and `row[0]` (by positional index), matching `sqlite3.Row` behavior!

### 5.5 CLI and Public API Design (`r2diaphora/diaphora_r2.py`, `scripts/`)

#### CLI (`r2diaphora`)
```text
usage: r2diaphora [-h] [-f] [-nbbs NBBS] [-o O] [-d {pdc,ghidra}] [-nd] [-a]
                  [-t TIMEOUT] [--db-backend {sqlite,mariadb}] [--db-dir DB_DIR]
                  [--pdb] [--slow] [--unreliable] [--relaxed] [--no-ml]
                  file1 [file2]
```
- Accepts either binary files (which are analyzed via radare2 and exported to DB) **or** pre-existing `.sqlite` database files (which skip export and go straight to diffing!).
- When `file2` is provided:
  - Runs Diaphora 3.5 diffing (`CBinDiff.diff(db2)`).
  - Saves `<file1>_vs_<file2>.diaphora` (SQLite diff results DB) AND renders `<o>.html` via `HtmlResults`.

#### Database Management CLI (`r2diaphora-db`)
- Works with both SQLite (default, managing cached `.sqlite` DBs in `~/.r2diaphora/dbs/`) and MariaDB (`--db-backend mariadb`, managing databases on the MariaDB server and credentials in `~/.r2diaphora/db.json`).

## 6. Builder Decisions (Defaulted per User Priority)

- **Default SQLite File Location:**
  - When running `r2diaphora <file1>` from CLI: defaults to `<file1>.sqlite` in the current directory (or `--db-dir` if specified), matching upstream Diaphora's `<idb>.sqlite` convention.
  - When calling `generate_db_for_file(filepath)` via the legacy Python API without `out_db`: stores `<sha256>.sqlite` in `~/.r2diaphora/dbs/` so existing scripts (`r2diaphora-bulk`, `HtmlResults`) work seamlessly without cluttering source directories.
- **Bundling Upstream Diaphora 3.5:**
  - Upstream Diaphora 3.5 files are vendored in `r2diaphora/upstream/` with an `UPSTREAM_VERSION` file recording the exact commit/tag (`3.5.0`), so future updates are a single directory sync.
- **Optional ML Dependencies:**
  - `scikit-learn`, `joblib`, `pandas`, and `cdifflib` are supported when installed (and listed in `extras_require` / `install_requires` as appropriate), falling back gracefully when absent just as upstream Diaphora 3.5 does.
