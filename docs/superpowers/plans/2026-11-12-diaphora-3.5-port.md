# Diaphora 3.5 Port for r2diaphora Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `r2diaphora` from Diaphora 2.0.6 to Diaphora 3.5 using an unmodified upstream core, a bulk-pre-fetched `ida*` translation layer for radare2 + `r2ghidra`, and a dual-backend database adapter (SQLite default, MariaDB supported), verified against IDA Pro on `calc.exe`.

**Architecture:** Unmodified Diaphora 3.5 files live under `r2diaphora/upstream/`. Before importing upstream modules, `r2diaphora/ida_shim` registers mock `idc`, `idaapi`, `idautils`, and `ida_*` modules in `sys.modules` backed by `R2BinaryCache` (which performs bulk `r2pipe` JSON queries once per binary and once per function), while `r2diaphora/db_backend.py` hooks `diaphora.sqlite3_connect` to provide native `sqlite3` by default or a SQL-translating MariaDB cursor wrapper when `--db-backend mariadb` is selected.

**Tech Stack:** Python 3.8+, `sqlite3`, `r2pipe`, `radare2` + `r2ghidra` (`pdg`/`pdgx`), `mysql-connector-python` (optional/MariaDB), `yattag`, `pytest`.

**Spec:** `docs/superpowers/specs/2026-11-12-diaphora-3.5-port-design.md`

## Global Constraints

- SQLite databases exported by `r2diaphora` MUST use the exact schema, table names, column names, and `VERSION_VALUE = "3.4"` from upstream Diaphora 3.5 (`db_support/schema.py`) so IDA Diaphora 3.5 and `r2diaphora` databases are 100% cross-compatible.
- Upstream Diaphora 3.5 files in `r2diaphora/upstream/` (`diaphora.py`, `diaphora_ida.py`, `diaphora_heuristics.py`, `diaphora_config.py`, `db_support/schema.py`, `codecut/`, `jkutils/`, `ml/`) MUST NOT be forked with inline `r2pipe` or `mysql.connector` queries.
- Zero `r2pipe` commands may be executed inside per-instruction loops (`decode_insn`, `get_bytes`, `get_operand_value`, `CodeRefsFrom`, `DataRefsFrom`, `GetCommentEx`, `get_switch_info` must all read from `R2BinaryCache` in memory).
- No `signal.SIGALRM` usage anywhere in the codebase; timeouts must use cross-platform `concurrent.futures.ThreadPoolExecutor` / `threading` so Windows works natively.
- Auto-named radare2 functions (`fcn.<hex>`) must be normalized to `sub_<hex>` and x86/x86_64 processor name to `"metapc"` (`"metapc64"` on 64-bit) for heuristic parity with IDA.

## Review Focus

1. **MariaDB SQL translation with `?` or `main.`/`diff.` inside string literals:** SQL strings containing `?` (e.g., mangled C++ names like `?__CxxUnhandledExceptionFilter@@YAJPEAU_EXCEPTION_POINTERS@@@Z`) must not have `?` replaced with `%s`; placeholder and schema replacement must skip single- and double-quoted SQL literals.
2. **PE64 `.pdata` zero-padded tail entries:** `section..pdata` is page-aligned (4096 bytes in `calc.exe` with ~264 bytes of entries followed by zeros); `.pdata` parsing must stop/skip entries where `BeginAddress == 0` or `EndAddress == 0` or outside executable segments.
3. **Instruction `decoded_size` / `mask` edge cases:** When `aoj` returns an empty/all-zero `mask` or operand `offb` subtraction would make `decoded_size <= 0`, `get_decoded_instruction` must clamp `decoded_size >= 1` and fall back to `ins.size` so `get_bytes` never returns `b""`.
4. **Malformed or empty `pdgx` XML from `r2ghidra`:** On 1-instruction thunks (`_XcptFilter_0`), `int3` stubs, or when `r2ghidra` emits warnings before XML, `decompile_function` must strip non-XML prefixes and return `None` cleanly on parse failure instead of raising `ET.ParseError`.
5. **Windows SQLite file lock on overwrite (`-f`) or `recreate_database()`:** Closing and removing open `sqlite3.Connection` objects from `diaphora._DATABASES` before calling `os.remove(db_path)` is required on Windows to avoid `PermissionError: [WinError 32]`.
